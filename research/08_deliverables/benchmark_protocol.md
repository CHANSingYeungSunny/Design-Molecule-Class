# Benchmark 协议（第 1 轮，冻结版）

本文件是**动模型之前**写下的实验约定。任何后续偏离都必须单独记录，不得静默修改。

定位：**「参考 MolRepBench 设计的扩展 benchmark」**，不是论文复现。
参考论文：*Rethinking Molecular Text Representations for LLMs: An Empirical Study*,
arXiv:2606.03057v1，2026-06-02。

---

## 1. 研究问题

固定**同一个 LLM、同一批分子、同一道题、同一套评分规则**，只改变分子的输入表示，
模型表现是否变化？Our Code 的优势与代价分别是什么？

**不预设 Our Code 最优。** 分任务报告准确率、回归误差与成本；不同量纲的指标
不加权求和成「总分」。

---

## 2. 与参考论文的关系

| 维度 | 参考论文 | 本研究 |
| --- | --- | --- |
| 表示 | 9 种文本表示 | 本轮 3 种：Our Code、SMILES、SELFIES |
| 任务 | 8 类（B1–B6、B9、B10） | 5 类，其中 4 类题目形式与其相近 |
| 数据 | ChEBI-20、ZINC250K | **仅 ChEBI-20 子集**（ZINC250K 留给后续独立实验） |
| 模型 | 16 个模型 / 5 个家族 | 1 个（你指定） |
| QED | **论文无此任务** | **本项目新增**，明确标注 |
| 图像 / 三维 | 论文未作为同设置主实验 | 本轮不实现 |
| 回归指标 | 正文用 Spearman，附录表述不一 | **事先声明用 MAE + Spearman**，不复制含混表述 |

**不同数据集、任务、模型的数字不能直接与论文数字比较并称「优于原论文」。**

## 3. 数据与划分

**来源**：ChEBI-20，取 MolT5 的 BSD-3-Clause 再发布版
（`github.com/blender-nlp/MolT5/tree/main/ChEBI-20_data`）。
分片 `test` + `validation`，共 6,601 行，SHA-256 记入 `dataset_manifest.json`。

**不使用 QM9**（本轮移除）；**不使用** MolRepBench 的数据包（该仓库无许可证）。

**筛选（在模型调用之前完成，剔除理由全部记录）**：

| 规则 | 内容 | 剔除 |
| --- | --- | --- |
| F1 | RDKit 能解析 | 0 |
| F2 | 源 SMILES 无立体化学标记（`@`、`/`、`\`） | 4,498 |
| F3 | Our Code 能解析 | 0 |
| F4 | Our Code 写出后可重新解析且原子/键数一致 | 0 |
| F5 | RDKit 认可 Our Code 输出为同一分子 | 0 |
| F6 | RDKit 规范 SMILES 也被 Our Code 读取 | 0 |
| F7 | 规范 SMILES 重新解析后不变（引用唯一） | 3 |
| F8 | SELFIES 能编码 | 1 |
| — | 重复分子（同一 canonical SMILES） | 2 |

F2 的处理是**排除**而非剥掉立体信息：教授原型声明立体化学超出范围并**拒绝**，
剥掉会改变化合物身份，相当于先丢信息再声称仍是原样本。

**结果**：池 **2,097** 个分子，dev **524** / test **1,573**，种子 20261005。

**划分规则**：**分子级**。同一母分子的所有变体（SMILES 遍历序、Our Code 记录序、
图像布局、题对两端）**必须同属一个 split**，防止泄漏。test 不用于调 prompt。

## 4. 表示的操作性定义

| 表示 | 每行到底输入什么 |
| --- | --- |
| **SMILES** | RDKit 2025.09.4 生成的 **canonical SMILES**（去立体）。Identity 正例改用 **rooted 非规范遍历**，两条串确实不同但描述同一分子，不是自己和自己比字符串。 |
| **SELFIES** | 由同一参考结构经 `selfies` 编码，并做**解码回环验证**（必须还原为同一 canonical SMILES）。 |
| **Our Code** | 教授原型 `to_code()` 产出的 `Molecule(...)` 构造文本。Identity 正例把原子/键**记录顺序重排**（同一张图、不同的合法排列）。发请求前**不转回 SMILES**。 |
| IMG / Graph2D / Graph3D / MolJSON | **本轮不实现**。注册表标 `implemented:false` 并注明原因，不写空壳。 |

统一原则：三种表示尽量保持**相同化学信息、相同氢处理、相同数值精度**；
长度、图像消耗、转换覆盖率另行统计。

## 5. 任务、标准答案与指标

标准答案**全部由 RDKit 2025.09.4 产生**，不经过核心类。
`Oracle`（参考值）与 `Evaluator`（评分规则）分离，均非「没有定义的两列总分」。

### T1 Identity
- 输入：同一表示下的一对结构。
- 输出：`{"same_molecule": bool}`。
- 正例＝同一结构的不同合法排列；负例**优先选同分子式的异构体**，其次选重原子数相同者，
  使「数原子个数」无法作答。
- 真值：RDKit canonical SMILES 相等，限定在共同支持范围内（去立体池）。
- 指标：**Accuracy**，辅以 Balanced Accuracy、混淆矩阵、有效回答率。

### T2 子结构识别（固定官能团清单，多标签）
- 输出：每个标签 `true/false`。
- 标签：固定 SMARTS 集合（`config/functional_groups.json`），RDKit 匹配。
  **按实测支持度冻结**：阳性 ≥20、阴性 ≥20 才启用。
  启用 13 个：aldehyde、ketone、ester、carboxylic_acid、amide、primary_amine、
  nitrile、alcohol、phenol、benzene_ring、alkyl_halide、aryl_halide、nitro。
  未启用并说明原因：`thiol`（阳性仅 14，不足 20）、`ether`、`sulfonamide`（配置层关闭）。
- 指标：**Macro-F1**（有效子集），并同时报**全样本惩罚版**（无效应答按全 false 计，规则已声明），
  辅以每标签 F1、阳性/阴性数量、有效回答率。
- 各表示**都用相同的自然语言官能团名**，不给任何表示额外结构答案。

### T3 结构理解（重原子计数）
- 输出：`{"C":n,"N":n,"O":n,"S":n}`。
- 元素按数据分布选定：C 95% 非零、O 88%、N 56%、**S 17%**。
  **未采用论文示例中的 F**：本池中 F 仅 4.9% 非零，恒答 0 就能拿高分，区分度不足。
- 指标：**Exact-match Accuracy**（四元素全对），另报每元素准确率与分布。
- 不设无计算定义的笼统 structure score。

### T4 QED 估计（**本项目新增任务**）
- 输出：`{"qed": 0..1}`。模型**不调用 RDKit、不执行代码、不访问评分器**。
- 参考值：RDKit `QED.qed` 默认权重（`WEIGHT_MEAN`）与 ADS 参数，
  已从安装版本读出并存入 `dataset_manifest.json`。
- 指标：**MAE**（主）+ **Spearman**（辅）；另报
  全样本有效回答率、`|误差| ≤ 0.05` 的**全样本成功率**。
  0.05 是**本项目预设起点，不是公认阈值**，已在 test 前冻结。
- MAE/Spearman 对有效数值计算并显式给 `n_valid/n_total`；非法、缺失、超范围答案
  **不消失也不裁剪**，在全样本成功率中记失败；缺答**不当作误差 0**。
- 明确禁止：先把表示转回 RDKit 算出同一个 QED 再填成模型成绩——那只是转换一致性检查。

### T5 基础描述符
- 本轮**只启用 HBD**（`{"hbd": int}`，Exact-match Accuracy）。
- HBA、logP、TPSA **已实现但本轮未运行**，报告中标「待测」，不混进主表。
- 单位注明：HBA/HBD 为计数；logP 无量纲（Crippen）；**TPSA 单位 Å²**。
- 失败处理与分母规则同 T4，预先固定。

## 6. 评分规则（先冻结，后运行）

- 每个预定样本都有状态：`ok` / `invalid` / `pending`。
- **无效应答**（解析失败或超出范围）：全样本指标记失败；**不裁剪、不默认某个正确类别**。
- **缺失应答**：在全样本成功率中记失败；在条件误差指标中排除**并显式给出 n**。
- 传输故障在声明的重试后仍失败 → `pending`，该格标「未完成」，**不缩分母充数**。
- 置信区间：95% **cluster bootstrap**（按母分子重采样），F1 与相关系数
  **在每次重采样内重新计算**，不是逐例分数简单平均。
- **不因少量 smoke 结果宣称显著更优。**

## 7. 公平比较与运行协议

1. 每张主表只对应**一个确切模型版本、同一数据集与 split、同一推理模式、同一工具权限**。
   换模型或换思考模式就另开表。
2. 模型**全程不调用外部工具、不执行 Our Code、不调用 RDKit**。
3. 固定任务措辞、输出 schema、few-shot 数量（本轮 **0-shot**）、温度（0）、
   top_p（1）、输出预算，**只有表示内容与一句必要格式说明变化**；
   记录完整 prompt 模板与 hash（每行记录存 `prompt_hash`）。
   三种表示都得到**同等原则**的说明，且都不含答案。
4. 每题**独立会话**，不共享其它表示的回答；调用顺序用固定种子打乱并记录。
5. 控制上下文长度但**不截断分子**；记录 token 用量、耗时；
   **没有真实价格依据就不报费用**，标「未知」，不估造。
6. 请求记录字段：`example_id, split, dataset_version, representation, task, model_id,
   prompt_hash, raw_response, parsed, label, status, usage, latency, run_id, cluster, cache_key`。
   **标签与内部 ID 不进入模型可见 prompt。**
7. 重试**只针对传输故障**（超时、连接、429、5xx）。**看到错答案后重试样一次是禁止的。**
8. 缓存键含数据、样本、表示、任务、prompt、模型版本与生成配置；
   重复试验必须用独立 run/seed，不得读缓存冒充新实验。

## 8. 规模与预算

| 配置 | 规模 | 用途 |
| --- | --- | --- |
| smoke | 每任务 8 题（Identity 正负各 4） | **仅检查管线**，不能据此宣称某表示最佳 |
| main | 每任务 200 题（Identity 正负各 100） | 正式比较；预算或标签支持不足时下调并说明 |
| 硬上限 | smoke 每次运行 ≤ **240** 次请求 | 代码强制，不可超 |

以上是**本项目默认值**，不是论文原样规模。

## 9. 本轮不做的事

- 不下载、不使用 QM9。
- 不训练/微调模型，不做生成优化循环，不做 docking、逆合成、ADMET。
- 不实现图像、Graph2D、Graph3D、MolJSON。
- 不复现教授已排除的原型扩展问题，不新增相应方法或「未来改进」章节。

## 10. 结果状态用词（全项目统一）

| 词 | 含义 |
| --- | --- |
| 数值 | 来自某次具名 run 的真实实测，可由代码从保存记录重新生成 |
| 待测 | 已实现但**从未对模型运行** |
| 未实现 | 明确不在本轮范围 |
| 模型不支持 | 该模型没有图像接口（本轮的 image 条件不适用） |
| N/A | 定义不适用 / 标签支持度不足 |

| 0 | **只有真的测得 0 才写 0** |

**模拟响应、旧测试成绩、人工猜测一律不得填入 benchmark 表。**

## 11. 运行后补记（addendum，2026-10-06）

以下是协议冻结**之后**实际运行时才发现的运维事实。补记不影响上面任何规则，
但读结果时必须知道。

### 11.1 实际使用的端点与模型

| 项目 | 实际值 |
| --- | --- |
| 模型 ID | `deepseek-v4.1-flash` |
| 地域 | `beijing` |
| base_url | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` |
| 说明 | 该主机由官方文档之外的实际探测确认：`/compatible-mode/v1/models` 返回 26 个模型，未带凭据返回 401 |

> 注意：环境里的 `ANTHROPIC_BASE_URL` 指向 `…/apps/anthropic`，那是 **Anthropic 协议**
> 路径，本 benchmark 的 OpenAI 兼容客户端**不能**使用；同一主机的
> `/compatible-mode/v1` 才是本客户端使用的地址。

### 11.2 关闭思考模式（**推理条件变更，必须单独成表**）

该模型默认开启思考。真实验证：

| 条件 | completion tokens | reasoning tokens | 返回内容 |
| --- | --- | --- | --- |
| 默认（思考开启） | 4096（触顶） | 4096 | **空**，`finish_reason=length` |
| `enable_thinking=false` | 9 | 0 | `{"qed": 0.419}` |

思考开启时模型把整个预算耗在推理上、正文为空，**无法评分**。
故本轮全部运行**关闭思考模式**（`run_config.json` → `generation.extra_body`）。
`reasoning_effort='none'` 与 `thinking.type='disabled'` 观测到同样效果。

**这是一次推理条件变更**：按第 7 节第 1 条，任何后续开启思考的试验必须**另开一张表**，
不得与本轮数字混在一起。

### 11.3 max_tokens 与截断

`probe-01` 用 512 上限，出现过 `finish_reason=length`、`reasoning_tokens=496`、
正文只剩约 15 tokens 而被截断成非法 JSON 的样本。
上限提高到 4096、并关闭思考后，`smoke-02` 的 120 条记录**0 条截断**。
每行记录新增 `truncated` 字段，便于把「配置性截断」与「模型答错」分开诊断。
截断是**配置问题**，不是模型能力结论；但被截断的记录同样按无效记入全样本指标，不剔除。

### 11.4 已完成的真实运行

| run id | 规模 | 结果 |
| --- | --- | --- |
| `probe-01` | Our Code × T3 × 8 | 7 有效 / 1 截断（配置问题），已废弃，配置修改后重跑 |
| `probe-02` | Our Code × T3 × 8 | 8/8 有效且全对 |
| `smoke-02` | 3 表示 × 5 任务 × 8 题 = 120 | **120/120 有效，0 截断**，累计 53,029 tokens |

`smoke-01` 在配置变更前启动，为避免把两种推理条件混进同一 run，其部分记录已删除，
数字不作为结果。**main 规模未运行。**

## 12. 协议冻结 v2（2026-10-06 核查后修订）

本节记录本轮核查后的**协议变更**。变更原因与证据见 `audit_findings_zh.md`。
旧协议下的产物保留原样，未覆盖。

### 12.1 区间与比较（对应 §三）

| 项目 | v1 | **v2（现行）** |
| --- | --- | --- |
| 比例型任务区间 | 仅 percentile bootstrap | **Wilson** 与 **Clopper–Pearson** **并列给出**；两者假定题项独立，仅在题项确为独立单例时可直接引用 |
| 依赖结构 | 未检查 | 每格输出 `cluster_summary`，标明题项是否为独立单例 |
| Identity 簇定义 | **只取一端** | **两个端点都算**；题对在任一端点被抽中时进入重采样 |
| 退化处理 | `[1.00, 1.00]` 直接展示 | 标 `degenerate=true` 并附解释：小样本全同侧**不等于**总体已达 100% |
| 表示间比较 | 无 | **`paired_comparison`**：同题配对、按簇做符号翻转置换；**不得**用区间重叠判断差异 |
| 多重比较 | 无 | 预声明比较族（同一任务内三个两两比较为一族），Holm–Bonferroni 校正 |
| Macro-F1 / MAE / Spearman 的 bootstrap | 每次重采样内重算 | 同（保持不变），并处理无支持类别、常数数组、相关未定义 |

**措辞规则**：不得再写「差别完全落在噪声里」。固定表述为
「当前样本量不足以可靠判断表示间的差异，观察到的差别需要扩大样本并进行配对分析」。
**main 达到 200 题不自动等于功效充分**，须做配对检验后再下结论。

### 12.2 官能团标签集（对应 §四）

- 操作集改为读取 `prepare` 写出的 `functional_groups.frozen.json`。
  v1 中该文件**只写不读**，导致实际提问 14 个标签（含 `thiol`）。
- 现行操作集：**13 个**（`thiol` 因池内阳性 14 < 阈值 20 停用）。
- 停用理由全部写明：`ether`（与酯/酚结构重复）、`sulfonamide`（刻意不照搬论文题组）、
  `thiol`（支持度不足）。
- 每标签输出 precision / recall / F1；**无阳性样本的标签标为「未启用」并从 Macro-F1 排除，
  不得记为满分**；zero-division 规则在代码内显式声明，不依赖库默认。

### 12.3 划分与泄漏（对应 §五）

- **数据集版本 `chebi20-molt5-v1-q1`**：调试阶段（`probe-01`/`probe-02`/`smoke-02`）
  触碰过的 **16 个分子**已从 dev/test 隔离（`quarantined.jsonl`）。
  隔离按**两个端点**计算，比只按单字段多找出 4 个题对伙伴分子。
- 现行规模：池 2,097 / 开发集 524 / **测试集 1,557** / 隔离 16。
- **测试集现已与调试过程独立**：调试用样本全部落在隔离集内。
- 旧 manifest 与旧冻结标签集保留在 `data/prepared/history/`。
- **划分来源声明**：dev/test 是本项目自行重划分，**不保留** ChEBI-20 或参考论文的标准协议。

### 12.4 重新评分的性质

`smoke-02` 的 15 个格子已用 v2 评分器**重新评分**。必须表述为
**「旧响应使用新版评分器重评」**，**不得**冒称新的模型实验：

- 模型调用未重跑，token 用量不变（仍为 53,029）；
- 提示词未改，原始响应文件未被改写（`clusters` 为派生的回填字段，写入 `scored.jsonl`）；
- T2 的 Macro-F1 因标签集由 14 改为 13 而发生变化（our_code 0.400→0.467、
  selfies 0.657→0.767、smiles 0.967 不变）。

### 12.5 仍未解决的限制

1. smoke 每格仅 8 题，**不足以支撑任何表示间比较**；本轮数字仍只说明管线通畅。
2. 13 个标签中只有 6 个在 smoke 样本中被命中，其余标为未启用。
3. `nitrile` 池内仅 28 个阳性，main 规模下若阳性不足需标 N/A 并说明，
   **不得**为凑数调整标签或阈值。
4. **main 未运行**；正式比较须在 main 规模、按 §12.1 的配对检验流程进行。
