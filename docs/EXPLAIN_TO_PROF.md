# 向教授解释实验过程

可以这样开场：

“之前报告只给了成绩，没有充分说明如何得到成绩。这次我把真实输入生成代码、五项任务prompt、独立参考答案、评分程序和原始响应连起来，并提供不调用模型的复算入口。它能把保存的回答重新算成同一张表。GitHub发布与fresh clone验收的完成状态另行记录。”

这项实验怎么做：先固定一批分子，然后把同一分子分别写成八种输入。每个任务的问法保持项目规定的模板，模型只看到表示和问题。RDKit在实验程序一侧生成参考答案，模型没有这些参考答案，也不会执行Our Code。回答保存后，评分器才对照参考值算分。

如果教授问“你的核心在哪里”：基础类在`molecule_core.py`，表示转换在`reps.py/reps_ext.py`；真正模型prompt在`tasks.py`；参考答案在`labels.py`；请求在`client.py`；冻结和日志在`runner.py`；评分在`scoring.py`。基础类沿用教授原型，我不能把它说成自己的新原创。我的报告要把这些环节与实际文件对应起来。

如果教授问“一个结果如何算出来”：看真实计数题`t3-our_code-71464601`。模型答C22/N1/O4/S2，参考是C21/N1/O4/S2；因为四个值必须全对，这题得0。所有该任务共同题按同规则平均，就是表格准确率。QED则取每题绝对误差后平均。官能团要分别算每一类的F1，再等权平均；它不是每题全对率。

如果教授问“你用了什么prompt”：展示`prompts/system.txt`与`benchmark_templates.json`，再打开`historical_our_code_examples.json`看真实完整请求。回答还要说明模型被问13类官能团，但主分数固定用10类；历史T2/T3示例双大括号是已披露的缺陷。

如果教授问“为什么不是论文复现”：原文9文本表示/8任务/16模型，我们8输入/5任务/1模型；数据划分、一次问题数量、JSON输出、QED及Our Code都是变化。原论文没有本项目完整的图片/3D实验，也没有Our Code基础类。逐项对应见PAPER_TO_PROJECT.md。

如果教授问“别人真的能复现吗”：仓库 https://github.com/CHANSingYeungSunny/Design-Molecule-Class 已发布。已验证源码提交是 `aac92e78a7d1b1f80653d59ec45252a3a612e45a`；我在与工作目录无关的新目录 clone 这个 commit，`test_baseline_core.py` 得 55 项 OK，`replay_table.py` 输出 "Historical replay passed: 40 frozen lists, all 40 table values match."，远端 Actions（ubuntu-24.04）同一 commit 为 completed/success。重新推理还需要服务和key，服务权重可能变，不能承诺新回答逐题一致。参考答案重建用 `scripts/rebuild_labels.py`，RDKit 重算 996 条、0 条不一致。

如果教授问“三条复现有什么区别”：A 是从保存的回答重算表格（验证"表能从数据重建"）；B 是用 RDKit 重新计算参考答案并逐项比对（验证"标准答案可复现"）；C 是重新调用模型（未执行，需要自备服务与预算）。只有 A 或只看教学例子，不能说标签重建已经通过。

如果教授问“Our Code的Identity满分能说明什么”：它是这200题上的描述性成绩。原三表示正负例的输入排序规则不同，可能有标签线索；题对还可能共享分子端点。后续应统一输入扰动规则并用独立题单验证，不能声称已证明最强同分子推理能力。

如果教授问“Our Code+H是否解决问题”：只完成结构一致性验证，没有模型消融成绩，不能说已经改善HBD。下一步应在开发集只改变氢信息，固定其余条件，再用未参与调试的新题验证。

提交前我应自己练习：打开一个历史请求，指出哪些字是分子、哪些字是问题、哪个文件生成参考答案、评分器用了哪条规则，然后运行复算命令并找到逐题输出。做到这些才能解释我理解了实验，而不是仅把AI生成文字交给教授。
